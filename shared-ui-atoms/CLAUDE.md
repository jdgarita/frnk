# shared-ui-atoms

Compose Multiplatform design system: tokens, theme engine, host-configurable theme, and a small set of `Frnk*` atoms built on `compose-unstyled` 2.x. Headless and unopinionated — **not** Material3.

## Contents

- `ui/tokens/` — design tokens (single source of truth, plain Kotlin objects).
  - `ColorTokens.kt` — `FrnkPrimitiveColors` (raw scales) and `FrnkColors.Light/Dark` (semantic).
  - `TypographyTokens.kt` — `FrnkTypography` (Material 3 scale).
  - `SpacingTokens.kt`, `ShapeTokens.kt`, `IconSizeTokens.kt` — Dp + Shape constants.
- `ui/theme/` — the theme engine.
  - `FrnkTheme.kt` — `ThemeProperty<T>` + `ThemeToken<T>` declarations for all axes, `LightPalette`/`DarkPalette` maps, `Appearance` enum + `LocalAppearanceController`, and the public `@Composable fun FrnkTheme(config, appearanceController, content)` built on `buildPlatformTheme`. The `appearanceController` defaults to a `remember`-scoped instance and is provided via `CompositionLocalProvider`, so the toggle works zero-config; hosts that need process-death survival can hoist their own controller (e.g. with `rememberSaveable` or a DataStore-backed flow) and pass it in.
  - **Token naming**: color tokens use the `color` prefix (`colorPrimary`, `colorOnPrimary`, `colorError`, …) so importing them doesn't shadow `kotlin.error()` or common local variable names. Shape tokens use `shape*`, string tokens `string*`, icon tokens `icon*`. Text-style tokens stay unprefixed (`bodyLarge`, `titleMedium`) — they don't collide with anything common.
  - `FrnkThemeConfig.kt` — immutable host config. Hosts pass `Map`s of token → override for any axis (light colors, dark colors, text styles, shapes, strings, icons) plus an optional `fontFamily: FontFamily?` that's applied to every default text style. Prefer `FrnkThemeConfig.Default` over `FrnkThemeConfig()` at call sites to avoid per-recomposition allocation.
  - `FrnkStrings.kt` / `FrnkIcons.kt` — default toolkit strings and icons + the `ThemeToken<String>` / `ThemeToken<ImageVector>` constants. Hosts override via `FrnkThemeConfig.stringOverrides` / `iconOverrides`.
- `ui/atoms/` — `Frnk*` atoms, each in its own file with an `@Immutable` `*State` class.
  - `FrnkText.kt` — sealed `FrnkTextState` (Text/Title/TitleMedium/HeadlineSmall/Body/BodyMedium/BodySmall/AppName).
  - `FrnkButton.kt` — `FrnkButtonState` + `FrnkButtonVariant` (Filled/Outlined/Ghost).
  - `FrnkIcon.kt` — `FrnkIconState`.
  - `FrnkIconButton.kt` — `FrnkIconButtonState`.
  - `FrnkDivider.kt` — sealed `FrnkDividerState` (Horizontal/Vertical).
  - `FrnkSwitch.kt` — `FrnkSwitchState`; an animated on/off toggle built on foundation primitives (`toggleable`, `Role.Switch`), no Material3.
  - `FrnkSegmentedControl.kt` — `FrnkSegmentedControlState` (options + selectedIndex); an n-way single-select pill group, used by the settings theme toggle.
  - `FrnkBottomNavBar.kt` — `FrnkBottomNavBarState` (`items: List<FrnkBottomNavItem>` + selectedIndex); a stateless, icon-only floating **pill** bottom nav. The selected tab fills with a 14% `colorPrimary` tint (`lerp(surface, primary, .14f)`) and its icon switches to `colorPrimary`; idle tabs are transparent with a `colorOnSurfaceVariant` icon (both crossfade via `animateColorAsState`). The wrapper around the pill is **transparent** (only the pill is filled) so when the bar floats over scrolling content the content stays visible around/behind it; over a plain background it looks identical. Pill geometry (48dp buttons, 6dp padding/gap, 10/16/14 wrapper insets) uses private `dp` constants — same precedent as `FrnkSwitch`. `FrnkBottomNavBarDefaults.BarHeight` exposes the bar's total reserved height for hosts to pad scrollable content with. Generic over items; the 3-tab product contract lives in `BottomNavScaffold`.
  - `FrnkTopAppBar.kt` — `FrnkTopAppBarState` (title + optional `navigationIcon` + `actions: List<FrnkTopAppBarAction>`); `FrnkTopAppBarDefaults.BarHeight` (56.dp) exposes the content-row height (status-bar inset excluded) for hosts that float the bar over edge-to-edge content. a leading-aligned title with an optional leading icon button (e.g. back) and a row of trailing action icon buttons, all over `colorBackground`/`colorOnBackground`. **Status-bar-safe by default**: applies `Modifier.windowInsetsPadding(WindowInsets.statusBars)` so it never draws under the system status bar in an edge-to-edge layout — set `applyStatusBarPadding = false` if the host already consumes that inset. **Search mode**: set `isSearchActive = true` (+ `searchQuery` / `searchPlaceholder`) and the bar swaps title+actions for an auto-focused `BasicTextField` with a leading "close search" button (`onSearchClose`) and a trailing "clear" button; edits stream through `onSearchQueryChange`. The host owns the flag — typically flipped on from `onActionClick`. `onNavigationClick` / `onActionClick(action)` are the title-mode callbacks.
- `ui/scaffolds/` — higher-than-atom, lower-than-feature page templates with a fixed UI shape and a configurable state class. Each scaffold ships **two** entry points: a stateless `*Content` composable (used by previews and advanced hosts that hoist their own state), and a VM-backed convenience wrapper that resolves a `Mvi`-based ViewModel via Koin (`koinViewModel { parametersOf(initialState) }`). A per-scaffold Koin module (`xxxScaffoldModule`) registers the VM; downstream Koin modules `includes(...)` it. Default copy comes from `FrnkStrings`; hosts override per-token through `FrnkThemeConfig.stringOverrides`.
  - `OnboardingScreen.kt` — `OnboardingScreen` (VM-backed) + `OnboardingScreenContent` (stateless). Close-X (top-right), `HorizontalPager` (configurable `pagerHeight: Dp? = null` — null fills remaining space, non-null pins exact height), animated pip indicator, Back/Next buttons that flip to "Get Started" on the last page.
  - `OnboardingScreenState.kt` — `OnboardingPageState` (title/description/icon, all reused atom states), `OnboardingScreenState`, `OnboardingIntent` (PageSelected/NextClicked/PreviousClicked/CloseClicked), `OnboardingEffect` (CloseRequested/Completed).
  - `OnboardingViewModel.kt` — pure UI-state machine, no injected deps.
  - `OnboardingScaffoldModule.kt` — `onboardingScaffoldModule` Koin module.
  - `SettingsScreen.kt` — `SettingsScreen` (VM-backed) + `SettingsScreenContent` (stateless). A scrollable list of `SettingsSectionState` cards plus an optional footer. Three row styles: a three-way theme segmented toggle, a clickable row (icon/title/subtitle/chevron), and a toggle row (icon/title/subtitle/switch). The headline renders only when `state.title` is non-blank — pass a blank title when the host already shows the screen title in a `FrnkTopAppBar` to avoid a duplicate heading. `contentPadding: PaddingValues = PaddingValues(FrnkSpacing.lg)` controls the scroll insets — bump the bottom when hosting under a floating bottom bar so the footer clears the pill.
  - `SettingsScreenState.kt` — `SettingsScreenState`, sealed `SettingsRowState` (`SettingsThemeRowState`/`SettingsClickableRowState`/`SettingsToggleRowState`), `SettingsSectionState`, `SettingsFooterState`, the sealed `SettingsAction` catalog (UpgradeToPro/RestorePurchases/ManageSubscription/ShowOnboarding/SendFeedback/RateApp/PrivacyPolicy/TermsOfService/Custom), `SettingsIntent` (ThemeSelected/ToggleChanged/RowClicked), `SettingsEffect` (AppearanceChanged/ToggleChanged/ActionInvoked).
  - `SettingsViewModel.kt` — pure UI-state machine, no injected deps; reduces theme/toggle changes into state **and** re-emits them as effects so the host applies the appearance / persists the toggle / performs the action.
  - `SettingsScaffoldModule.kt` — `settingsScaffoldModule` Koin module.
  - `BottomNavScaffold.kt` — `BottomNavScaffold` (VM-backed) + `BottomNavScaffoldContent` (stateless). Owns **which tab is selected** and overlays the floating `FrnkBottomNavBar` (bottom-aligned) on top of the full-height selected destination, so content scrolls visibly behind the pill. The `tabContent: @Composable (tab: BottomNavTab, contentPadding: PaddingValues) -> Unit` slot is handed a bottom inset (= `FrnkBottomNavBarDefaults.BarHeight`) to apply to scrollable content. It is **not** a nav back-stack — the host renders each tab, e.g. mounting `SettingsScreen` for the Settings tab. Pass the optional `collapsibleBars: CollapsibleBarsState?` (the same instance the destinations' `FrnkScreenScaffold`s use) to make the bar slide down off-screen on scroll-down and back on scroll-up, in lock-step with the top bar.
  - `FrnkScreenScaffold.kt` — `FrnkScreenScaffold(topBar, collapsibleBars, bottomInset, contentPadding, …callbacks, content)`. The standard **screen template**: a `FrnkTopAppBar` floating over a single edge-to-edge scrollable `content` area, with both the top bar and the host's floating bottom bar collapsing on scroll (driven by the shared `collapsibleBars`). Content draws behind both bars; the `content(contentPadding)` slot receives a merged `PaddingValues` that already reserves the top bar's full height (status-bar inset + bar) and the `bottomInset`, so the first/last items clear the bars at rest. Layout scaffold (no MVI/ViewModel) — the bar is driven purely by `topBar` + its callbacks, mirroring `FrnkTopAppBar`.
  - `CollapsibleBarsState.kt` — `CollapsibleBarsState` + `@Composable rememberCollapsibleBarsState()`. A single "collapse on scroll" coordinator observed by **both** a screen's top bar and its floating bottom bar so they hide/reveal in lock-step. Exposes a `NestedScrollConnection` (registered by `FrnkScreenScaffold` above the scrolling content) that drives `collapseFraction` (0 shown → 1 hidden) 1:1 with the finger and snaps to the nearer end on fling/release; each bar translates by its own height. Call `reset()` when swapping the visible screen (e.g. a tab change) so the new screen starts with bars shown.
  - `BottomNavScaffoldState.kt` — `BottomNavTab` (key/icon/label), `BottomNavScaffoldState` (tabs + selectedIndex, non-empty invariant, `selectedTab` accessor), `BottomNavIntent` (TabSelected), `BottomNavEffect` (TabSelected — re-emitted only on an actual change).
  - `BottomNavViewModel.kt` — pure UI-state machine, no injected deps; reduces the selected index and re-emits the change as an effect (no-op on the already-selected tab).
  - `BottomNavScaffoldModule.kt` — `bottomNavScaffoldModule` Koin module.
  - `BottomNavDefaults.kt` — `@Composable rememberBottomNavScaffoldState(middleTab, …)` builds the toolkit's standard **3-tab** state (fixed Home + host-configurable middle + fixed Settings), resolving Home/Settings icon+label from `iconNavHome`/`stringNavHome` and `iconSettings`/`stringSettings`.
  - `SettingsDefaults.kt` — `@Composable rememberDefaultSettingsState(version, appearance, isPro, …)` builds the batteries-included catalog (Appearance, Notifications, Subscription, Support, Legal) + "Made in 🇨🇷 by JD with ☕" footer from `FrnkStrings`/`FrnkIcons`.
  - `FeedbackEmailLauncher.kt` — `@Composable rememberFeedbackEmailLauncher(appName, appVersion, recipient = FeedbackEmail.DEFAULT_RECIPIENT, …)` returns a `() -> Unit` that opens the platform mail composer prefilled with an app/OS/device diagnostics block. Pure Compose Multiplatform: builds a `mailto:` URI (via `shared-utils`' `FeedbackEmail`/`EmailDraft`) and hands it to `LocalUriHandler`, so it works on Android + iOS with no platform wiring. Wire it to `SettingsAction.SendFeedback` from a `SettingsScreen` `onEffect` handler; default recipient is `hello@jdgarita.dev`, overridable per host. Subject/prompt default to the `stringFeedbackSubject` / `stringFeedbackBodyHint` `FrnkStrings` tokens. (OS/version/device come from `PlatformInfo`, the only `expect/actual` — it lives in `shared-utils`, not here, to keep this module platform-free.)

## Source sets

- `commonMain` — production code (tokens, theme, atoms).
- `commonDebug` — `@Preview` composables for every atom. Sits between `commonMain` and each platform source set (`androidMain`, `iosArm64Main`, `iosSimulatorArm64Main` all `dependsOn` it). Uses the multiplatform `androidx.compose.ui.tooling.preview.Preview` annotation from `org.jetbrains.compose.ui:ui-tooling-preview`. New preview files go under `src/commonDebug/kotlin/dev/jdgarita/frnk/ui/atoms/previews/`. Wrap content in `PreviewSurface(appearance = ...)` so the preview renders under a real `FrnkTheme` against the chosen palette.

  **Caveat:** AGP 9's `com.android.kotlin.multiplatform.library` plugin has a single `androidMain` compilation (no `compileAndroidDebug`/`compileAndroidRelease` split), so today `commonDebug` sources also end up in release AARs. They're inert `@Composable` functions and R8 strips them — but if you need true debug-only exclusion (size budget, license posture, etc.), promote `commonDebug` to a sibling Gradle module that only the demo / debug consumers depend on.

## Dependencies

- `api(projects.sharedUiApi)` — atoms expose the same MVI types feature ViewModels use.
- `api(compose.runtime / foundation / ui)` so downstream modules don't redeclare Compose deps.
- `api(koin.compose, koin.compose.viewmodel)` — `koinViewModel()` works at call sites without extra wiring.
- `implementation(compose-unstyled.{primitives,theming,platformtheme,button,icon,separators})` — kept `implementation` so the consumer surface stays slim.
- `implementation(icons-lucide)` — default icons in `FrnkIcons.kt`. Hosts can override every icon, so consumers don't have to take a Lucide dependency unless they reference Lucide icons at call sites.

## Rules

- **No Material3.** Don't add `compose.material3` — atoms wrap `com.composeunstyled.*` headless primitives (`UnstyledButton`, `UnstyledIcon`, `UnstyledHorizontalSeparator`, `UnstyledVerticalSeparator`, `Text`) and resolve styling via `Theme[colors][...]` / `Theme[textStyles][...]`.
- **Atoms read tokens, not hard-coded values.** Use `Theme[colors][colorPrimary]` not `Color(0xFF...)`. Use `FrnkSpacing.md` not `16.dp` for spacing constants.
- **Atoms are platform-agnostic** — `commonMain` only. No `LocalContext`, `UIViewController`, etc.
- **Every atom has a `*State` class.** State is `@Immutable`, fields default to sensible values, and callbacks (`onClick`, etc.) are separate parameters on the composable.
- **Host configuration flows through `FrnkThemeConfig`.** Don't expose ad-hoc setters or extra composition locals for per-axis overrides; that contract is the single entry point.
- ViewModel logic (MVI contracts, base class) stays in `:shared-ui-api`. This module is for tokens, theme, and composables only.

# shared-ui-atoms

Compose Multiplatform design system: tokens, theme engine, host-configurable theme, and a small set of `Frnk*` atoms built on `compose-unstyled` 2.x. Headless and unopinionated — **not** Material3.

## Contents

- `ui/tokens/` — design tokens (single source of truth, plain Kotlin objects).
  - `ColorTokens.kt` — `FrnkPrimitiveColors` (raw scales) and `FrnkColors.Light/Dark` (semantic).
  - `TypographyTokens.kt` — `FrnkTypography` (Material 3 scale).
  - `SpacingTokens.kt`, `ShapeTokens.kt`, `IconSizeTokens.kt` — Dp + Shape constants.
- `ui/theme/` — the theme engine.
  - `FrnkTheme.kt` — `ThemeProperty<T>` + `ThemeToken<T>` declarations for all axes, `LightPalette`/`DarkPalette` maps, `Appearance` enum + `LocalAppearanceController`, and the public `@Composable fun FrnkTheme(config, appearanceController, content)` built on `buildPlatformTheme`. The `appearanceController` defaults to a `remember`-scoped instance and is provided via `CompositionLocalProvider`, so the toggle works zero-config; hosts that need process-death survival can hoist their own controller (e.g. with `rememberSaveable` or a DataStore-backed flow) and pass it in. `FrnkTheme` also installs a **press ripple** as the ambient `LocalIndication` (`config.indication ?: rememberFrnkRipple()`), so every interactive atom and every host `Modifier.clickable`/`UnstyledButton` under the theme gets touch feedback with no per-component wiring. It likewise installs **haptics** (`LocalFrnkHaptics`, via the `haptics: HapticFeedback = rememberFrnkHaptics()` param — hoistable like `appearanceController` for process-death survival).
  - `ui/haptics/` — the **haptics binding** over the Compose-free contract in `:shared-ui-api` (`HapticType` / `HapticFeedback` / `HapticEngine`). `MultiHapticEngine` maps each `HapticType` to a `top.ltfan.multihaptic` primitive composition and plays it through a `Vibrator` (no-op when `isVibrationSupported` is false, e.g. an iOS simulator); `LocalFrnkHaptics` (default `NoOpHapticFeedback`) is the ambient `HapticFeedback`; `rememberFrnkHaptics(enabled)` resolves the platform `Vibrator` via `multihaptic-compose`'s `rememberVibrator()` (reads `LocalContext` on Android — **no Context plumbing**) and wraps it in `DefaultHapticFeedback`. It **rebuilds the `Vibrator` on every return to foreground** (keyed off an `ON_STOP`→`ON_START` counter) because multihaptic 0.3.2 doesn't restart its iOS `CHHapticEngine` after the app is backgrounded — without this, haptics silently die after the user leaves to (say) the App Store and comes back, until the process is killed. The `DefaultHapticFeedback` wrapper stays stable across rebuilds (so the enabled flag survives) and `MultiHapticEngine` reads the current `Vibrator` through a provider lambda. `HAPTICS_TOGGLE_ID = "haptics"` is the stable id of the default Settings toggle (mirrors `GOD_MODE_TOGGLE_ID`). Like the ripple, haptics is treated as a UI-feedback concern, not a swappable backend SDK — so it lives here rather than in an api/impl module pair.
  - `FrnkRipple.kt` — `@Composable fun rememberFrnkRipple(color = Color.Unspecified, bounded = true, radius = Dp.Unspecified): IndicationNodeFactory`, the public ripple factory built on `com.composables:ripple-indication` (the compose-unstyled vendor's theme-agnostic ripple — **not** Material3; it only pulls JetBrains' `material-ripple` renderer, no `MaterialTheme`). `Color.Unspecified` follows the call site's content color. Hosts pass it to `clickable(indication = …)` on their own components, or restyle the global default via `FrnkThemeConfig.indication`.
  - **Token naming**: color tokens use the `color` prefix (`colorPrimary`, `colorOnPrimary`, `colorError`, …) so importing them doesn't shadow `kotlin.error()` or common local variable names. Shape tokens use `shape*`, string tokens `string*`, icon tokens `icon*`. Text-style tokens stay unprefixed (`bodyLarge`, `titleMedium`) — they don't collide with anything common.
  - `FrnkThemeConfig.kt` — immutable host config. Hosts pass `Map`s of token → override for any axis (light colors, dark colors, text styles, shapes, strings, icons) plus an optional `fontFamily: FontFamily?` that's applied to every default text style, and an optional `indication: Indication?` that replaces the default ripple (`null` → the bundled ripple; pass a no-op `Indication` to disable press feedback). Prefer `FrnkThemeConfig.Default` over `FrnkThemeConfig()` at call sites to avoid per-recomposition allocation.
  - `FrnkStrings.kt` / `FrnkIcons.kt` — default toolkit strings and icons + the `ThemeToken<String>` / `ThemeToken<ImageVector>` constants. Hosts override via `FrnkThemeConfig.stringOverrides` / `iconOverrides`.
- `ui/atoms/` — `Frnk*` atoms, each in its own file with an `@Immutable` `*State` class. **Interactive atoms auto-fire haptics on interaction** via `LocalFrnkHaptics.current.perform(...)` (gated by the global enabled flag, so it's a no-op when haptics are off): `FrnkButton` / `FrnkIconButton` → `HapticType.Click`; `FrnkSwitch` / `FrnkSegmentedControl` / `FrnkBottomNavBar` → `HapticType.Selection` (the multi-option selection atoms only fire on an actual change; a switch fires on every toggle since each toggle *is* a change). New interactive atoms should follow suit. Gating is **global-only** today (the one enabled flag); a per-instance override (e.g. a `*State.haptic: HapticType?` field to retype or silence a specific atom) is the natural future extension — deliberately omitted for now.
  - `FrnkSkeleton.kt` — `FrnkSkeleton` (`@Immutable`) + `FrnkSkeletonHighlight` (Shimmer/Fade/None) + the internal `Modifier.frnkSkeleton(...)` helper. **State architecture (host-alignment refactor):** each interactive/content atom's `*State` is now a **`sealed interface` with a `Content` data class + a `data object Skeleton`** (e.g. `FrnkButtonState.Content` / `FrnkButtonState.Skeleton`), and the composable `when`-switches: the `Skeleton` branch paints a token-styled loading block (via `Modifier.frnkSkeleton(FrnkSkeleton(enabled = true), shape = <natural shape>)`) and is non-interactive (no clickable/toggleable node at all). `FrnkSkeleton`/`frnkSkeleton` stay the **internal rendering** machinery for that branch — they're no longer a public `*State` field. **Exception:** `FrnkTextState` is the one atom that **keeps** a per-subtype `skeleton: FrnkSkeleton` field (so a parent that knows the text can render a *content-sized* text skeleton via `FrnkTextState.Title(..., skeleton = …)`) **and** adds a `data object Skeleton` for the content-agnostic case. All skeleton color/shape/highlight values resolve from theme tokens — nothing hardcoded. Backed by the vendored `ui/placeholder/` package (see Source sets / Rules).
  - `FrnkText.kt` — sealed `FrnkTextState` (Text/Title/TitleMedium/HeadlineSmall/Body/BodyMedium/BodySmall/AppName).
  - `FrnkButton.kt` — `FrnkButtonState` + `FrnkButtonVariant` (Filled/Outlined/Ghost).
  - `FrnkIcon.kt` — `FrnkIconState`.
  - `FrnkIconButton.kt` — `FrnkIconButtonState`.
  - `FrnkDivider.kt` — sealed `FrnkDividerState` (Horizontal/Vertical).
  - `FrnkSwitch.kt` — `FrnkSwitchState`; an animated on/off toggle built on foundation primitives (`toggleable`, `Role.Switch`), no Material3.
  - `FrnkSegmentedControl.kt` — `FrnkSegmentedControlState` (options + selectedIndex); an n-way single-select pill group, used by the settings theme toggle.
  - `FrnkBottomNavBar.kt` — `FrnkBottomNavBarState` (`items: List<FrnkBottomNavItem>` + selectedIndex); a stateless, icon-only floating **pill** bottom nav. The selected tab fills with a 14% `colorPrimary` tint (`lerp(surface, primary, .14f)`) and its icon switches to `colorPrimary`; idle tabs are transparent with a `colorOnSurfaceVariant` icon (both crossfade via `animateColorAsState`). The wrapper around the pill is **transparent** (only the pill is filled) so when the bar floats over scrolling content the content stays visible around/behind it; over a plain background it looks identical. Pill geometry (48dp buttons, 6dp padding/gap, 10/16/14 wrapper insets) uses private `dp` constants — same precedent as `FrnkSwitch`. `FrnkBottomNavBarDefaults.reservedHeight` (a `@Composable` `Dp` = body + the bottom system-nav inset the pill floats above) is the value hosts pad scrollable content with; the bare-body `BarHeight` is `internal`. The atom itself is position-agnostic — the bottom-pinned call site (e.g. `BottomNavScaffoldContent`) applies the system-nav inset, not the atom. Generic over items; the 3-tab product contract lives in `BottomNavScaffold`.
  - `FrnkTopAppBar.kt` — `FrnkTopAppBarState` (title + optional `navigationIcon` + `actions: List<FrnkTopAppBarAction>`); `FrnkTopAppBarDefaults.BarHeight` (56.dp) exposes the content-row height (status-bar inset excluded) for hosts that float the bar over edge-to-edge content. a leading-aligned title with an optional leading icon button (e.g. back) and a row of trailing action icon buttons, all over `colorBackground`/`colorOnBackground`. **Status-bar-safe by default**: applies `Modifier.windowInsetsPadding(WindowInsets.statusBars)` so it never draws under the system status bar in an edge-to-edge layout — set `applyStatusBarPadding = false` if the host already consumes that inset. **Search mode**: set `isSearchActive = true` (+ `searchQuery` / `searchPlaceholder`) and the bar swaps title+actions for an auto-focused `BasicTextField` with a leading "close search" button (`onSearchClose`) and a trailing "clear" button; edits stream through `onSearchQueryChange`. The host owns the flag — typically flipped on from `onActionClick`. `onNavigationClick` / `onActionClick(action)` are the title-mode callbacks.
- `ui/molecules/` — **Molecules tier** of Atomic Design (P4-1): small compositions of existing atoms + tokens, above `ui/atoms/` and below `ui/scaffolds/`. Each has an `@Immutable *State`, separate callback params before `modifier`, tokens-only styling, a `@Preview` in `commonDebug/.../ui/molecules/previews/`, and a recorded skeleton decision. Interactive molecules reuse the automatic ripple (`LocalIndication`) + fire `LocalFrnkHaptics` like the atoms — don't re-wire.
  - `FrnkListRow.kt` — `FrnkListRowState` (title + optional subtitle + optional leading `FrnkIconState` + skeleton) + `FrnkListRow(state, onClick?, modifier, trailing?, swipe?, onSwipeAction, surfaceColor)`. Icon → weighted title/subtitle column → trailing slot (chevron/switch/badge). `onClick` makes the whole row tappable (ripple + `HapticType.Click`, both gated off while loading). Skeleton: **yes** — the whole row collapses to one `shapeMedium` block. **Optional swipe**: pass `swipe: FrnkSwipeableState?` to wrap the row in `FrnkSwipeable` (off by default — `null` renders byte-for-byte the old row; suppressed while the skeleton shows). While swiping, the sliding row paints an opaque `surfaceColor` (token, **default `colorBackground`**) so the action panel only shows once dragged aside — pass the host's backdrop when the row sits on a non-default surface (e.g. a `colorSurface` card). Taps report through `onSwipeAction`.
  - `FrnkSwipeable.kt` (+ `FrnkSwipeAction.kt`, `FrnkSwipeController.kt`) — `FrnkSwipeableState` (`behavior: FrnkSwipeBehavior { Dismiss, Reveal }` + `direction: FrnkSwipeDirection { Left, Right, Both }` + `leftActions`/`rightActions: List<FrnkSwipeAction>` + `threshold` + `enabled`) + `FrnkSwipeable(state, onAction, modifier, controller, contentBackground?, onSwipeProgress?, content)`. The generic swipe-to-action primitive usable around **any** content: drag the foreground aside to reveal token-styled action buttons (**Reveal** holds open a button row — tap an action, or tap the content to close; **Dismiss** fires the side's first action on release past `threshold`, then snaps back). A side is draggable only when its action list is non-empty (no rubber-banding over an empty gap); `contentBackground` (token, `null` = none) paints an opaque, shape-clipped fill behind otherwise-transparent content. The action layer is its own composable so the per-frame offset read invalidates only it, not the wrapped `content()`. `FrnkSwipeAction` carries an `icon: FrnkIconState` + `ThemeToken<Color>` `containerColor`/`contentColor` (default `colorError`/`colorOnError`) + stable `key` — **no lambda in the `@Immutable`**, following `FrnkTopAppBarAction`; the molecule reports taps through `onAction(action)`. Engine is pure Compose Foundation (`detectHorizontalDragGestures` + `Animatable` offset in the hoistable `FrnkSwipeController`); haptics via `LocalFrnkHaptics` (`Selection` on threshold-cross, `Click` on a reveal tap, `Success` on a dismiss commit). `Left`/`Right` are **physical** (not RTL-mirrored today — a future `start`/`end` API is the natural extension). Skeleton: **no, by design** — swipe is interaction chrome; the wrapped content owns its skeleton and callers gate the gesture off (`enabled = false`) while it shows. **Headless reimplementation of [stevdza-san/Swipeable-KMP](https://github.com/stevdza-san/Swipeable-KMP) (MIT) — no source copied, no Material3** (the upstream artifact hard-depends on `compose.material3`, which this module forbids).
  - `FrnkLabeledValue.kt` — `FrnkLabeledValueState` (label + value + `FrnkLabeledValueOrientation { Inline, Stacked }` + skeleton) + `FrnkLabeledValue(state, modifier)`. Muted label paired with a `TitleMedium` value. Skeleton: **yes** — the label is static chrome, the **value** carries the skeleton (only the figure collapses).
  - `FrnkEmptyState.kt` — `FrnkEmptyStateState` (icon + title + optional subtitle + optional actionLabel) + `FrnkEmptyState(state, onActionClick?, modifier)`. Centered icon/title/subtitle + optional `FrnkButton` CTA. Skeleton: **no, by design** — an empty state is a *terminal* zero-content state, not a loading state (you skeletonize the eventual content and only fall back to the empty state once loading finished empty); a skeleton *of* one would never show.
- `ui/organisms/` — **Organisms tier** of Atomic Design (P4-2): self-contained UI *sections* composed from molecules + atoms + tokens, above `ui/molecules/` and below `ui/scaffolds/`. Same rules as molecules — `@Immutable *State`, separate callbacks before `modifier`, tokens-only styling, a `@Preview` in `commonDebug/.../ui/organisms/previews/`, a recorded skeleton decision, automatic ripple/haptics (don't re-wire). Pure stateless view code, previews only — no unit tests (P4-4 added Compose UI tests for the highest-value atoms; molecules/organisms stay previews-only — see the `androidHostTest` source set below).
  - `FrnkSectionCard.kt` — `internal fun <T> FrnkSectionCard(rows, modifier, title?, footnote?, row)`. The **single source of the titled-card chrome** (optional uppercase title + `shapeCard`/`colorSurface` card + `FrnkDivider`-between-rows + `animateContentSize()` + optional footnote) with a `row(index, item)` content slot. Shared by the public `FrnkListSection` organism (homogeneous `FrnkListRow` rows) **and** the Settings scaffold's private `SettingsSection` (a heterogeneous sealed row hierarchy) — the chrome lives here once; only the row rendering differs per caller. `internal` because hosts compose sections via those higher-level entry points, not this primitive.
  - `FrnkListSection.kt` — `FrnkListSectionState` (rows: `List<FrnkListRowState>` + optional title + optional footnote) + `FrnkListSection(state, modifier, onRowClick?, trailing?)`. A thin organism over `FrnkSectionCard`: stacks `FrnkListRow` molecules as the rows. `onRowClick(index)` makes rows tappable; `trailing(index)` is a per-row slot (chevron/switch/badge). Skeleton: **yes, carried by the rows** — enable `skeleton` on individual `FrnkListRowState`s (each collapses to a block) rather than a section-level flag, so a partially-loaded list skeletonizes per row; the card/title/dividers are static framing.
  - `FrnkProfileHeader.kt` — `FrnkProfileHeaderState` (name + avatar `FrnkIconState` + optional subtitle + stats: `List<FrnkLabeledValueState>` + skeleton) + `FrnkProfileHeader(state, modifier)`. A `shapeCard` card: a circular `colorPrimaryContainer` avatar chip + name (`Title`) / subtitle (muted `BodyMedium`), with an optional even row of `FrnkLabeledValue` stat tiles (forced `Stacked`) below. Skeleton: **yes, passed through** — the one flag drives every child (avatar, name, subtitle, each stat value collapse to blocks) and the avatar chip **drops its brand fill while loading** so its rim doesn't peek around the glyph skeleton (same precedent as `FrnkSwitch`).
- `ui/scaffolds/` — higher-than-atom, lower-than-feature page templates with a fixed UI shape and a configurable state class. Each scaffold ships **two** entry points: a stateless `*Content` composable (used by previews and advanced hosts that hoist their own state), and a VM-backed convenience wrapper that resolves a `Mvi`-based ViewModel via Koin (`koinViewModel { parametersOf(initialState) }`). A per-scaffold Koin module (`xxxScaffoldModule`) registers the VM; downstream Koin modules `includes(...)` it. Default copy comes from `FrnkStrings`; hosts override per-token through `FrnkThemeConfig.stringOverrides`.
  - `OnboardingScreen.kt` — `OnboardingScreen` (VM-backed) + `OnboardingScreenContent` (stateless). Close-X (top-right), `HorizontalPager` (configurable `pagerHeight: Dp? = null` — null fills remaining space, non-null pins exact height), animated pip indicator, Back/Next buttons that flip to "Get Started" on the last page.
  - `OnboardingScreenState.kt` — `OnboardingPageState` (title/description/icon, all reused atom states), `OnboardingScreenState`, `OnboardingIntent` (PageSelected/NextClicked/PreviousClicked/CloseClicked), `OnboardingEffect` (CloseRequested/Completed).
  - `OnboardingViewModel.kt` — pure UI-state machine, no injected deps.
  - `OnboardingScaffoldModule.kt` — `onboardingScaffoldModule` Koin module.
  - `SettingsScreen.kt` — `SettingsScreen` (VM-backed) + `SettingsScreenContent` (stateless). A scrollable list of `SettingsSectionState` cards plus an optional footer. Three row styles: a three-way theme segmented toggle, a clickable row (icon/title/subtitle/chevron), and a toggle row (icon/title/subtitle/switch). The headline renders only when `state.title` is non-blank — pass a blank title when the host already shows the screen title in a `FrnkTopAppBar` to avoid a duplicate heading. `contentPadding: PaddingValues = PaddingValues(FrnkSpacing.lg)` controls the scroll insets — bump the bottom when hosting under a floating bottom bar so the footer clears the pill.
  - `SettingsScreenState.kt` — `SettingsScreenState`, sealed `SettingsRowState` (`SettingsThemeRowState`/`SettingsClickableRowState`/`SettingsToggleRowState`/`SettingsStatusRowState` — the last a non-interactive icon+title+trailing-badge-pill row, e.g. the "Pro Member" `PRO` badge), `SettingsSectionState`, `SettingsFooterState`, the sealed `SettingsAction` catalog (UpgradeToPro/RestorePurchases/ManageSubscription/ShowOnboarding/SendFeedback/RateApp/PrivacyPolicy/TermsOfService/Custom), `SettingsIntent` (ThemeSelected/ToggleChanged/RowClicked/VersionTapped), `SettingsEffect` (AppearanceChanged/ToggleChanged/ActionInvoked). Section cards `animateContentSize()`, so a row appearing/disappearing (e.g. the Subscription section flipping Free→Pro) settles smoothly instead of popping the layout.
  - `SettingsViewModel.kt` — pure UI-state machine, no injected deps; reduces theme/toggle changes into state **and** re-emits them as effects so the host applies the appearance / persists the toggle / performs the action.
  - `SettingsScaffoldModule.kt` — `settingsScaffoldModule` Koin module.
  - `BottomNavScaffold.kt` — `BottomNavScaffold` (VM-backed) + `BottomNavScaffoldContent` (stateless). Owns **which tab is selected** and overlays the floating `FrnkBottomNavBar` (bottom-aligned, permanently visible) on top of the full-height selected destination, so content scrolls visibly behind the pill. The `tabContent: @Composable (tab: BottomNavTab, contentPadding: PaddingValues) -> Unit` slot is handed a bottom inset (= `FrnkBottomNavBarDefaults.reservedHeight`, the pill body plus the system-nav inset it floats above) to apply to scrollable content. It is **not** a nav back-stack — the host renders each tab, e.g. mounting `SettingsScreen` for the Settings tab.
  - `FrnkScreenScaffold.kt` — `FrnkScreenScaffold(topBar, containerColor, bottomInset, contentPadding, …callbacks, content)`. The standard **screen template**: a `FrnkTopAppBar` pinned at the top over a single edge-to-edge scrollable `content` area. Both the top bar and the host's floating bottom bar stay fixed on the viewport while content scrolls underneath. It paints `containerColor` (default `Theme[colors][colorBackground]`, overridable to `colorSurface` / `Color.Transparent`) behind the whole screen, so every screen on this template follows the active light/dark palette without each host painting its own background. Content draws behind both bars; the `content(contentPadding)` slot receives a merged `PaddingValues` that already reserves the top bar's full height (status-bar inset + bar) and the `bottomInset`, so the first/last items clear the bars at rest. Layout scaffold (no MVI/ViewModel) — the bar is driven purely by `topBar` + its callbacks, mirroring `FrnkTopAppBar`.
  - `BottomNavScaffoldState.kt` — `BottomNavTab` (key/icon/label), `BottomNavScaffoldState` (tabs + selectedIndex, non-empty invariant, `selectedTab` accessor), `BottomNavIntent` (TabSelected), `BottomNavEffect` (TabSelected — re-emitted only on an actual change).
  - `BottomNavViewModel.kt` — pure UI-state machine, no injected deps; reduces the selected index and re-emits the change as an effect (no-op on the already-selected tab).
  - `BottomNavScaffoldModule.kt` — `bottomNavScaffoldModule` Koin module.
  - `BottomNavDefaults.kt` — `@Composable rememberBottomNavScaffoldState(middleTab, …)` builds the toolkit's standard **3-tab** state (fixed Home + host-configurable middle + fixed Settings), resolving Home/Settings icon+label from `iconNavHome`/`stringNavHome` and `iconSettings`/`stringSettings`.
  - `SettingsDefaults.kt` — `@Composable rememberDefaultSettingsState(version, appearance, isPro, …)` builds the batteries-included catalog (Appearance, Notifications, Subscription, Support, Legal) + minimalist "Built by JD in 🇨🇷" footer from `FrnkStrings`/`FrnkIcons`. The Subscription section enforces a strict Free/Pro matrix: **Free** → "Upgrade to Pro" + "Restore Purchases"; **Pro** → a "Pro Member" status badge + "Manage Subscription" (Upgrade and Restore hidden).
  - `FeedbackEmailLauncher.kt` — `@Composable rememberFeedbackEmailLauncher(appName, appVersion, recipient = FeedbackEmail.DEFAULT_RECIPIENT, …)` returns a `() -> Unit` that opens the platform mail composer prefilled with an app/OS/device diagnostics block. Pure Compose Multiplatform: builds a `mailto:` URI (via `shared-utils`' `FeedbackEmail`/`EmailDraft`) and hands it to `LocalUriHandler`, so it works on Android + iOS with no platform wiring. Wire it to `SettingsAction.SendFeedback` from a `SettingsScreen` `onEffect` handler; default recipient is `hello@jdgarita.dev`, overridable per host. Subject/prompt default to the `stringFeedbackSubject` / `stringFeedbackBodyHint` `FrnkStrings` tokens. (OS/version/device come from `PlatformInfo`, the only `expect/actual` — it lives in `shared-utils`, not here, to keep this module platform-free.)
- `ui/mvi/` — the **Compose binding layer** for the MVI engine (whose pure contracts/base live in `:shared-ui-api`). This is the public state-hosting primitive host apps build their own screens on, so they don't hand-roll state/effect collection.
  - `FrnkMviScreen.kt` — `@Composable fun <S,I,E> FrnkMviScreen(viewModel, topBar, …, onEffect: ((E)->Unit)? = null, content: @Composable (state, onIntent, contentPadding) -> Unit)`. Binds an `MviViewModel` to `FrnkScreenScaffold`: collects state with `collectAsStateWithLifecycle`, hands the content slot `(state, viewModel::send, padding)`, and forwards the scaffold's top-bar callbacks + `bottomInset`/`contentPadding`. Effects are consumed by an internal `EffectCollector` **only when `onEffect` is non-null** — the effect channel is single-consumer, so pass `null` when a shared VM's effects are collected elsewhere (the demo's Home tab does exactly this).
  - `EffectCollector.kt` — `@Composable fun <E> EffectCollector(effects: Flow<E>, minActiveState = STARTED, onEffect)`. The toolkit's one correct way to consume a one-shot effect stream: lifecycle-gated via `repeatOnLifecycle` (no toast/navigation fired at a backgrounded screen; buffered effects drain on resume) and `rememberUpdatedState`-wrapped so a recomposed handler is observed without restarting the collector. Use it instead of `LaunchedEffect(vm){ vm.effects.collect { … } }`. The three VM-backed scaffolds (`SettingsScreen`/`OnboardingScreen`/`BottomNavScaffold`) use it.
- `ui/nav/` — the **Compose binding for the toolkit navigation layer** (the Compose-free route contract + `FrnkNavigator` abstraction live in `:shared-ui-api`). A thin wrapper over JetBrains CMP `navigation-compose`: the toolkit ships the `NavHost` machinery, the **host owns the back-stack instance**. Navigation integrates with the MVI effect channel — a ViewModel emits a navigation `UiEffect`, and a single `EffectCollector` above the host routes it into a `FrnkNavigator`.
  - `FrnkNavHost.kt` — `FrnkNavHost(navController, startRoute, modifier, builder)` over `NavHost`; `rememberFrnkNavController()` over `rememberNavController()`; and the reified `NavGraphBuilder.frnkComposable<T : Any> { route -> … }` over `composable<T>` + `toRoute<T>()` (decodes the back-stack entry into the typed `@Serializable` route, so destinations read arguments type-safely).
  - `FrnkNavigatorAdapter.kt` — `rememberFrnkNavigator(navController): FrnkNavigator` adapts a host-owned `NavController` to the Compose-free `FrnkNavigator`, translating `FrnkNavOptions` into nav-compose `navOptions { popUpTo(…){ saveState } }` for multiple-back-stack tab switching.

## Source sets

- `commonMain` — production code (tokens, theme, atoms).
- `androidHostTest` — **Compose UI tests for the highest-value atoms (P4-4).** The atoms are headless,
  fully state-hoisted composables with no reducer, so behavior is verified by driving a real composition
  with `runComposeUiTest` and querying the semantics tree. These run as JVM **host** tests
  (`testAndroidHostTest` — what CI gates) under **Robolectric**, so the suite needs no device/emulator.
  They live here rather than `commonTest` because the Compose UI-test runtime + Robolectric have no
  common/iOS variant (mirrors `shared-database-impl`'s androidHostTest JDBC driver). All test classes
  extend `RobolectricComposeTest` (carries `@RunWith(RobolectricTestRunner)` + `@Config(sdk=[34])` +
  `GraphicsMode.NATIVE`). Test-only deps (`org.jetbrains.compose.ui:ui-test` by direct coordinate,
  `androidx.compose.ui:ui-test-manifest`, `org.robolectric:robolectric`) are scoped to this source set
  and `withHostTest { isIncludeAndroidResources = true }` lets Robolectric inflate the test host — **no
  production/`commonMain` surface change, XCFrameworks stay clean.** Covered today: `FrnkSwitch`,
  `FrnkSegmentedControl`, `FrnkTopAppBar` (search mode). Other atoms/molecules/organisms remain
  previews-only by default; add a test here when an atom grows non-trivial state-driven behavior.
- `commonDebug` — `@Preview` composables for every atom. Sits between `commonMain` and each platform source set (`androidMain`, `iosArm64Main`, `iosSimulatorArm64Main` all `dependsOn` it). Uses the multiplatform `androidx.compose.ui.tooling.preview.Preview` annotation from `org.jetbrains.compose.ui:ui-tooling-preview`. New preview files go under `src/commonDebug/kotlin/dev/jdgarita/frnk/ui/atoms/previews/`. Wrap content in `PreviewSurface(appearance = ...)` so the preview renders under a real `FrnkTheme` against the chosen palette.

  **Caveat:** AGP 9's `com.android.kotlin.multiplatform.library` plugin has a single `androidMain` compilation (no `compileAndroidDebug`/`compileAndroidRelease` split), so today `commonDebug` sources also end up in release AARs. They're inert `@Composable` functions and R8 strips them — but if you need true debug-only exclusion (size budget, license posture, etc.), promote `commonDebug` to a sibling Gradle module that only the demo / debug consumers depend on.

## Dependencies

- `api(projects.sharedUiApi)` — atoms expose the same MVI types feature ViewModels use.
- `api(compose.runtime / foundation / ui)` so downstream modules don't redeclare Compose deps.
- `api(koin.compose, koin.compose.viewmodel)` — `koinViewModel()` works at call sites without extra wiring.
- `api(androidx-lifecycle-runtime-compose)` — `collectAsStateWithLifecycle` / `repeatOnLifecycle` behind `FrnkMviScreen` + `EffectCollector`; `api` so host apps inherit lifecycle-aware collection for their own screens. Same `org.jetbrains.androidx.lifecycle` group/version as the viewmodel artifact.
- `api(androidx-navigation)` — JetBrains CMP `org.jetbrains.androidx.navigation:navigation-compose` behind the `ui/nav/` primitives; `api` so hosts can reference `NavController`/`NavHostController` for their own graphs. Pure Kotlin/Compose — **no native cinterop**, so `DemoKit`/`FrnkKit` XCFrameworks stay clean. The `kotlin-serialization` plugin is applied here so the reified `frnkComposable<T>` / `toRoute<T>` can resolve serializers for concrete routes.
- `implementation(compose-unstyled.{primitives,theming,platformtheme,button,icon,separators})` — kept `implementation` so the consumer surface stays slim.
- `implementation(icons-lucide)` — default icons in `FrnkIcons.kt`. Hosts can override every icon, so consumers don't have to take a Lucide dependency unless they reference Lucide icons at call sites.
- `implementation(multihaptic-core, multihaptic-compose)` — `top.ltfan.multihaptic` behind `LocalFrnkHaptics`. A UI-feedback library like the ripple, kept `implementation` so it stays an internal detail. multihaptic ships its own Android/iOS impls (**no native cinterop**), so `DemoKit`/`FrnkKit` XCFrameworks stay clean and the Android `VIBRATE` permission self-merges from `multihaptic-core`'s manifest.

## Rules

- **No Material3.** Don't add `compose.material3` — atoms wrap `com.composeunstyled.*` headless primitives (`UnstyledButton`, `UnstyledIcon`, `UnstyledHorizontalSeparator`, `UnstyledVerticalSeparator`, `Text`) and resolve styling via `Theme[colors][...]` / `Theme[textStyles][...]`. This is also why the skeleton effect is **vendored** under `ui/placeholder/` (a material-free subset of RevenueCat's Apache-2.0 `placeholder-compose`) rather than taken as a dependency — the published artifact hard-depends on Material3 in `commonMain`. See `ui/placeholder/NOTICE.md` for the vendoring rationale and the list of modifications. Don't add the upstream `com.revenuecat.purchases:placeholder` artifact.
- **Atoms read tokens, not hard-coded values.** Use `Theme[colors][colorPrimary]` not `Color(0xFF...)`. Spacing/padding and icon sizes are **host-overridable theme axes** too: read them in composable bodies as `Theme[spacing][spacingMd]` / `Theme[iconSizes][iconSizeMd]` (not `FrnkSpacing.md` / `16.dp`). The `FrnkSpacing` / `FrnkIconSize` objects remain the **default-value source** feeding `DefaultSpacing`/`DefaultIconSizes` (the role `FrnkColors` plays for the palette) — fine to reference directly only in non-composable default-argument expressions (`@Immutable *State` fields, `@Composable` fun default params) where `Theme[...]` can't be read; those keep the bundled default. Hosts override via `FrnkThemeConfig.spacingOverrides` / `iconSizeOverrides`.
- **Atoms are platform-agnostic** — `commonMain` only. No `LocalContext`, `UIViewController`, etc.
- **Every atom has a `*State` class.** State is `@Immutable`, fields default to sensible values, and callbacks (`onClick`, etc.) are separate parameters on the composable.
- **Sealed `*State` with a `Skeleton` object.** Every component with multiple visual states models its `*State` as a **`sealed interface`** with a `Content` data class and a `data object Skeleton` (add an `Error` data class where the component has a real error visual). The composable `when`-switches; the `Skeleton` branch renders a non-interactive placeholder via `Modifier.frnkSkeleton(FrnkSkeleton(enabled = true), shape = <natural shape token>)` (no clickable/toggleable node) and the `Content` branch renders the real UI. Showcase the `Skeleton` state in the demo + a `@Preview`. Skeleton styling is token-driven only — never hardcode skeleton colors/shapes. Components that are genuinely single-state or terminal — `FrnkDivider` (pure divider), `FrnkEmptyState` (terminal zero-content), `FrnkSwipeable` (interaction chrome) — stay non-sealed / skip the `Skeleton` object; note why. `FrnkText` is the documented exception that **also** keeps a per-subtype `skeleton` field for content-sized text skeletons (see `FrnkSkeleton.kt` above). The reference example lives in `HOST_ALIGNMENT.md` → "Component style guide".
- **Host configuration flows through `FrnkThemeConfig`.** Don't expose ad-hoc setters or extra composition locals for per-axis overrides; that contract is the single entry point.
- ViewModel logic (MVI contracts, base class) stays in `:shared-ui-api`. This module is for tokens, theme, and composables only.
